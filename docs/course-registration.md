# 수업 등록과 구성 재사용

관리자는 `/app#/manage/:programId`에서 **기본정보 → 원본 차시 → 수업 구성 → 미리보기·공개**의 네 단계로 등록한다. 한 단계씩 표시하며 이전/다음과 임시 저장을 제공한다. 임시 저장은 보고 있던 단계와 차시를 유지한다. 기존 전역 메뉴를 재사용한다.

| 단계 | 등록 내용 |
|---|---|
| 기본정보 | 수업명·소개·학교급/학년/교과 연결·학습 주제·자료 용도·공통 웹앱 주소 |
| 원본 차시 | 원본 차시의 제목·시간·자료·학생 제출·진로기록 계획을 한 화면에서 편집 |
| 수업 구성 | 원본 차시를 골라 필요한 구성을 복사하고 생략 과정의 시작 자료·설명을 보완 |
| 미리보기·공개 | 구성별 자료·제출·기록 계획을 확인하고 저장 또는 공개 |

노트북에서는 왼쪽 차시 목록과 오른쪽 차시 편집 화면을 사용한다. 모바일에서는 위쪽 차시 선택과 아래쪽 고정 이전/다음·임시 저장을 사용한다. 선택한 차시의 웹앱·PPT·활동지·교안, 학생 사진·문서·글 제출 설정과 진로기록 계획을 함께 편집한다. 순서 변경 시 편집 중인 차시를 계속 선택하고, 차시 삭제 시 남은 차시로 이동한다.

## 한 번 등록하고 재사용

- 차시 제목을 한 줄씩 붙여넣는다. 엑셀의 제목/웹앱 주소 두 열도 지원한다. 구성당 1~50차시, 1~12개 구성이다.
- 공통 웹앱 주소는 비어 있는 모든 차시에 연결한다. 기존 차시 전용 주소나 HTML 파일은 덮어쓰지 않는다.
- 첫 번째 구성을 원본으로 편집하며 원본 구성 자체는 삭제할 수 없다. 수업 구성 단계에서 가져올 구성과 사용할 차시를 선택한다. 선택한 차시의 제목·자료·시간·제출 및 기록 계획을 독립 복사한다. 새 구성 변경은 원본에 영향을 주지 않는다.
- 10·5·3차시는 예시이며 고정 프리셋이 아니다. 교안 내용 자체를 자동 압축하지 않으므로 생략 단계의 시작 자료·연결 설명은 교사가 보완한다.
- 자료 여러 개 등록은 파일별 차시/종류를 명시적으로 지정한다. 파일명으로 임의 배치하지 않는다. 중복 칸은 업로드 전 차단하며 완료된 파일은 재시도 때 건너뛴다. 파일 확인 API는 동일 업로드 경로의 동시 확인·응답 유실 재시도에 기존 파일 ID를 반환하며, 달라진 이름·형식·크기는 409로 거부한다.
- 웹앱/PPT/활동지/교안을 전부 강제하지 않는다. 공개할 차시는 제목과 자료 또는 제출 받기가 필요하다. 진로기록 계획을 선택하면 제출 받기·제출 안내·학생 원본·한 줄 활동 설명을 입력한다.

기존 `/app#/resources/:programId` 자료 관리와 교사용 `/app#/course/:programId` 열람을 유지한다. 자료 등록만으로 학생 공유 권한이 열리지는 않는다. 교사는 공개된 구성을 수업 보드에 적용하고 학생 웹앱·활동지 공유를 명시적으로 선택한다.

## 저장 범위

기존 settings의 `course_plan:<programId>` 문서(version 1, revision CAS)를 사용한다. 관리자만 수정하고 교사는 공개 프로그램의 공개 구성만 읽는다. 다른 수업 파일/차시는 연결할 수 없다. 새 schema나 migration은 없다. ACADEMY_ID 호환 뷰 저장은 기존대로 닫혀 있다.

학생의 사진·문서·글 제출은 기존 Hub 게시판 기능을 사용한다. 이 변경의 진로기록 항목은 **어떤 활동 설명과 학생 원본을 남길지 설계하는 설정**이다. 이 설정 저장이나 게시판 제출만으로 중앙 Career Log에 새 Record가 생성되지는 않는다. 제출 안내·학생 원본 계획도 기존 학생 화면에 자동 적용된다고 보장하지 않는다. 실제 저장 연결은 준비 중이며, 외부 웹앱 내부 결과는 앱별 연결을 확인해야 한다.

이번 배포에는 학생 식별·세션 변경, Career 저장·조회·재시도 API, 원본 파일 별도 보관, Edge Function 변경을 포함하지 않는다. 기존 앱별 Career Log 동작과 원본 기록은 유지한다.

## 검증 범위

`npm run check`는 기존 회귀와 API/트랜잭션 대역 및 실제 UI 스크립트의 이벤트 테스트다. 단계·차시 이동, 자료·제출·기록 계획 입력 보존, 순서 변경·삭제, 구성 독립 복사, 같은 단계 임시 저장과 실패 후 재시도를 검사한다. 이 테스트는 실제 브라우저 레이아웃이나 운영 Career Record 저장 검증을 대체하지 않는다. 실제 모바일/태블릿/노트북 레이아웃과 업로드는 배포 후 별도로 확인한다.


## 학년·교과로 등록하고 찾기

프로그램 관리와 교사 수업 목록에서 **학교급 → 학년 → 교과** 트리로 찾는다. 모바일에서는 ‘교육과정 분류’를 눌러 필터를 펼친다. 검색·공개 상태 필터와 함께 사용할 수 있다. 여러 경로에 연결한 프로그램도 결과 목록에서는 한 번만 표시하며, 트리의 숫자는 해당 경로의 프로그램 수다.

등록 첫 단계의 ‘학년·교과 연결’에서 연결을 추가한다. 예를 들어 `초등학교 / 2학년 / 국어`와 `초등학교 / 3학년 / 과학`을 각각 등록한다. 이때 초2 과학이나 초3 국어까지 자동으로 연결하지 않는다. 교과 이름은 제안 목록에서 고르거나 직접 입력한다. 제안 목록은 공식 성취기준 검증이나 자동 교육과정 매핑이 아니며 등록자가 연계 내용을 확인한다.

- 한 프로그램에 최대 40개의 연결. 초등학교 1~6학년, 중·고등학교 1~3학년 지원.
- 학습 주제는 자유 입력이며 검색에 포함한다. 차시 자료와 전체/축약 구성은 그대로 재사용한다.
- ‘테스트·검증용’은 관리자가 명시적으로 지정하는 자료 용도다. 파일명이나 제목으로 추측해 자동 이동/삭제하지 않는다. 공개 권한을 대신하지 않으므로 교사에게 보이면 안 되는 테스트 수업은 비공개로 둔다.
- 분류가 없으면 ‘미분류’, 학년만 있으면 해당 학년의 ‘교과 미지정’에서 찾는다. 기존 `초2` 같은 학년은 최초 편집 시 연결로 가져오며 기존 카테고리를 교과로 추측하지 않는다. 모든 연결을 지워 저장하면 이전 학년으로 되돌아가지 않는다.
- `course_plan.plan.curriculum`에 `{links:[{school,grade,subject}],topic,purpose}`로 함께 저장한다. 서버가 형식·개수·학년 범위를 검증하고 중복 연결을 정리한다. 수업 구성의 기존 revision 충돌 방지를 함께 사용한다.
- 교사에게는 공개된 수업 구성의 분류만 내려보낸다. 관리자 임시저장 분류는 교사 목록에 노출하지 않는다.
- 이 분류는 프로그램을 찾기 위한 정보다. 학생 식별자나 Career Record에 태그를 추가하지 않는다.
