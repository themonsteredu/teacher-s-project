# 수업 등록 구성 편집기

- 등록/편집: `/app#/manage/:programId` (관리자)
- 기존 원본 차시·파일·링크 관리: `/app#/resources/:programId`
- 교사용 구성 자료 열람: `/app#/course/:programId`

## 등록 단위

수업 → 운영 구성(자유로운 이름, 1~12개) → 차시(구성당 1~50개) → 웹앱/PPT/활동지/교안.
10·5·3차시는 예시일 뿐 고정 프리셋이 아니다. 차시마다 여러 원본 차시 참조, 시간, 생략 단계의 시작 자료 설명을 입력한다. 파일은 기존 program_files를 참조해 여러 구성에서 재사용한다. URL도 연결할 수 있다. 구성 삭제/차시 제외는 원본 차시·파일을 삭제하지 않는다.

## 저장과 공개

기존 Hub settings의 `course_plan:<programId>` 키에 version 1 JSON 문서를 저장한다. 별도 migration이나 Career Log schema 변경은 없다. 이 키는 공통 getSettings 응답에서 제외된다. 관리자만 저장하며 기존 로그인·권한·사이트 접근 게이트를 사용한다. 교사는 공개된 프로그램의 명시적으로 공개한 구성만 읽는다. 임시 저장하면 구성은 초안으로 전환되며, 기존 일반 자료 공개 상태는 유지된다.

revision과 기존 문자열 값 비교를 함께 사용하여 동시 수정 손실을 막는다. 다른 수업의 파일/차시를 참조하면 400, 오래된 편집은 409. HTTPS 링크와 기존 내부 자료 경로만 허용한다. 공개 전 모든 차시 제목·4종 자료·선택한 기록 설정을 검사한다. 기존 단일 자료 관리 기능은 보존한다.

ACADEMY_ID 기반 호환 뷰에서는 CAS 저장 어댑터가 검증되지 않았으므로 새 구성 저장은 503으로 닫는다. 현재 DB 이관이나 호환 뷰 변경을 수행하지 않는다.

## 활동 기록의 경계

기록 설정은 제출 조건, 저장할 학생 원본, 사람이 읽는 한 줄 설명의 설계 자료다. ingest 권한, 프로그램 allowlist, student_id, 점수/정답은 설정하지 않는다. 기록 계획을 저장하거나 웹앱 주소를 연결해도 Career Log에 INSERT되지 않는다.

실제 학생 보드의 구성 선택·자료 자동 공유·구성별 진도 및 앱별 제출/Career Log 연동은 이번 등록 편집기의 범위에 포함되지 않는다. 교사 자료 열람 화면도 학생 보드 자료 공유를 별도로 해야 한다고 표시한다. 기존 접근 규칙을 우회하지 않는다.

## 검증

`npm run check`: 문법, 기존 회귀, 저장/권한/공개/동시수정 API 테스트, 실제 편집 스크립트 이벤트 테스트. SQL/API 저장소는 격리된 테스트 대역이며 운영 DB 저장 검증으로 간주하지 않는다.
실제 브라우저 반응형 검수와 Preview 저장·업로드 검수는 배포 한도 해제 후 필요하다.
