# 수업 등록과 구성 재사용

관리자는 `/app#/manage/:programId`에서 기본정보 → 수업 구성 → 구성별 자료 → 활동 기록 → 확인·공개 순으로 등록한다. 한 단계씩 표시하며 이전/다음과 임시 저장을 제공한다. 기존 전역 메뉴를 재사용해 편집기 안의 중복 사이드바를 제거했다.

## 한 번 등록하고 재사용

- 원본 차시 제목을 한 줄씩 붙여넣는다. 엑셀의 제목/웹앱 주소 두 열도 지원한다. 구성당 1~50차시, 1~12개 구성이다.
- 공통 웹앱 주소는 비어 있는 모든 차시에 한 번에 연결한다. 기존 차시 전용 주소나 HTML 파일은 덮어쓰지 않는다.
- 구성 추가에서 원본 구성과 사용할 차시를 선택한다. 선택한 순서의 제목·자료·시간·제출 및 기록 설정을 독립 복사한다. 새 구성 변경은 원본에 영향을 주지 않는다. 교안 내용 자체를 자동 압축하지 않으며 생략 단계의 시작 자료는 교사가 보완한다.
- 자료 여러 개 등록은 파일별 차시/종류를 명시적으로 지정한다. 파일명으로 임의 배치하지 않는다. 중복 칸은 업로드 전 차단하며 완료된 파일은 재시도 때 건너뛴다. 파일 확인 API는 같은 업로드 경로를 재시도해도 같은 파일 ID를 반환한다.
- 웹앱/PPT/활동지/교안을 전부 강제하지 않는다. 차시 제목과 자료 또는 제출 받기가 필요하다. 기록 모드라면 제출 안내·원본 안내·한 줄 설명과 제출 받기가 필요하다.

기존 `/app#/resources/:programId` 자료 관리, 교사용 `/app#/course/:programId` 열람은 유지한다. 자료 등록은 수업 보드의 공유 권한을 부여하지 않는다. 교사가 공개된 구성을 보드에 적용하고 학생 웹앱·활동지 공유를 명시적으로 선택해야 한다.

## 저장과 기록

기존 settings의 `course_plan:<programId>` 문서(version 1, revision CAS)를 사용한다. 관리자만 수정하고 교사는 공개 프로그램의 공개 구성만 읽는다. 다른 수업 파일/차시는 연결할 수 없다. 새 schema나 migration은 없다. ACADEMY_ID 호환 뷰 저장은 기존대로 닫혀 있다.

기록 설정 저장 자체는 Career Record를 만들지 않는다. 기록 모드인 차시에서 학생이 Hub 결과물을 실제 제출한 후 서버가 제출 원본을 저장한다. 완료 판정은 제목 + 글 또는 검증된 파일 유무이며 정답/점수와 무관하다. 자유문장 제출 안내는 학생에게 보여주는 지시문이지 자동 채점 규칙이 아니다. 외부 웹앱 내부 데이터는 자동 수집하지 않는다.

운영에 적용하려면 같은 변경의 Edge Function과 Hub 환경변수/코드를 함께 준비해야 한다. 상세한 원본 보관·학생 세션·재시도 계약은 [학생 제출](student-submissions.md)을 따른다.

## 검증 범위

`npm run check`는 API/트랜잭션 대역 및 실제 UI 스크립트의 이벤트 테스트다. 운영 DB 저장이나 실기기 브라우저 검증을 대체하지 않는다. 실제 모바일/태블릿/노트북 레이아웃, Preview 업로드와 Career Record 확인은 배포 후 별도로 필요하다.
